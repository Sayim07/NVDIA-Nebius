### Mandatory Rollback Plan  

| Trigger | Action | Responsible | Validation |
|---------|--------|-------------|------------|
| **CVE disclosure** impacting any listed package (FastAPI, PyJWT, Uvicorn, Pydantic, OpenAI SDK, Next.js, React, TailwindCSS, Framer‑Motion) | 1. Immediately pin the offending package to the last known‑good version (see table).<br>2. Create a hotfix branch `rollback/<pkg>-<cve-id>`.<br>3. Deploy to staging via CI pipeline.<br>4. Run smoke‑test suite (auth gateway healthcheck, JWT validation, Next.js page render).<br>5. If tests pass, promote to production; otherwise iterate. | Lead Engineer (Sayim) + DevOps | Automated unit/integration tests + manual sanity check on `staging-url` |
| **Failed health‑check** (e.g., 5xx error rate > 2% for 5 min) | Same rollback steps as above, using the version currently deployed in the previous successful release (tagged `titan-v2.4.0`). | Site Reliability Engineer | Health‑endpoint (`/health`) returns 200; latency < 150 ms |
| **Dependency‑upgrade regression** (post‑upgrade test failure) | Revert to the pre‑upgrade version captured in the release notes; re‑run the upgrade after fixing the root cause. | Release Manager | Post‑rollback test suite passes; monitoring shows baseline metrics. |

**Rollback Procedure (example for PyJWT CVE):**  

1. `git checkout main && git pull`  
2. Edit `requirements.txt`: change `pyjwt==2.8.0` → `pyjwt==2.7.0` (last known‑good).  
3. Commit: `git commit -m "Rollback PyJWT to 2.7.0 due to CVE‑XXXX-XXXX"`  
4. Tag: `git tag titan-v2.4.1-pyjwt-rollback`  
5. Push: `git push origin main titan-v2.4.1-pyjwt-rollback`  
6. CI pipeline builds Docker image `titan:2.4.1-pyjwt-rollback` and deploys to `https://titan-internal-staging.company.io`.  
7. Run automated test suite (`pytest` + `playwright`).  
8. On success, promote to prod via approved release channel; otherwise, investigate and repeat.

All rollbacks must be logged in the incident‑response ticket with timestamps, CVE IDs (if applicable), and verification artifacts.
