

**Executive Summary**  
Project Titan (v 2.4.1) is a zero‑trust auth/API‑gateway microservice built on Python FastAPI + Uvicorn and a Next.js 14 frontend. The last formal audit was 2026‑10‑10. Weekly CVE verification for **PyJWT** and **Next.js** is mandated. Live Tavily scouting returned no new vulnerability disclosures directly affecting the listed dependencies; all packages appear to be at their latest stable releases as of the current intel window. No actionable CVEs were identified, but continuous monitoring remains essential.

### Mandatory Rollback Plan  

**Trigger Conditions** (any one initiates rollback):  
1. Publication of a CVE ≥ 7.0 (CVSS v3) impacting PyJWT, Next.js, FastAPI, Uvicorn, Pydantic, or OpenAI SDK.  
2. Automated security scan (e.g., Dependabot, Snyk) reports a new vulnerability after the weekly check.  
3. Post‑deployment health‑check failure (≥ 5 % error rate or latency > 2× baseline) correlated with a dependency change.  
4. Explicit directive from the Security Operations Center (SOC) due to external threat intel.

**Rollback Procedure**  

| Step | Action | Owner | Validation |
|------|--------|-------|------------|
| 1 | **Freeze current state** – tag the offending commit: `git tag titan/rollback/$(date +%Y%m%d%H%M)` | Release Engineer | Tag visible in repository |
| 2 | **Revert to last known‑good version** – checkout the previous release tag (e.g., `titan/v2.4.0`) and create a new branch: `git checkout titan/v2.4.0 -b rollback/titan/v2.4.0` | Release Engineer | Branch reflects v2.4.0 code |
| 3 | **Update lockfiles** – run `pip install -r requirements.txt && npm ci` to ensure exact dependency versions match the reverted code. | DevOps | `pip list` and `npm ls` show expected versions |
| 4 | **Run automated test suite** – execute backend unit/integration tests (`pytest`) and frontend Cypress smoke suite. | QA Lead | All tests pass (≥ 95 % success) |
| 5 | **Deploy to staging** – push the rollback branch to the internal CI pipeline; promote to `titan-internal-staging.company.io`. | DevOps | Staging health‑check endpoint returns 200 OK, latency < baseline |
| 6 | **Smoke‑test staging** – validate auth token issuance, API gateway routing, and UI load (< 2 s FCP). | SRE | No errors, latency within SLA |
