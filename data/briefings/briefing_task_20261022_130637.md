### Mandatory Rollback Plan  

**Trigger Conditions** (any one initiates rollback):  
1. Detection of an active exploit matching a CVE that affects any Titan dependency (e.g., PyJWT JWT‑validation bypass).  
2. Automated security scanner (e.g., Dependabot, Snyk) reports a new critical/high severity vulnerability in a locked version.  
3. Post‑deployment health checks fail (error rate >5% or latency SLA breach) and logs indicate dependency‑related crashes.  
4. Manual security incident report confirms compromise tied to a dependency version.

**Rollback Procedure** (executed by Release Engineer, verified by Lead Maintainer Sayim):  

| Step | Action | Details |
|------|--------|---------|
| 1 | **Freeze** | Halt all new deployments to staging/prod via CI pipeline lock (e.g., `git tag rollback-<date>`). |
| 2 | **Identify Last Good Commit** | Use `git log --grep="release"` or release notes to find the most recent commit that passed security scan (baseline: `titan-v2.4.0` tagged 2026‑09‑15). |
| 3 | **Checkout & Verify** | `git checkout titan-v2.4.0`; run `pip install -r requirements.txt` and `npm ci`; execute full unit + integration test suite. |
| 4 | **Deploy to Staging** | Push the verified commit to the staging branch; trigger automated deployment to `https://titan-internal-staging.company.io`. |
| 5 | **Smoke Test** | Run synthetic transaction suite (auth token issuance, API gateway routing) against staging URL; confirm <2% error rate and latency <150 ms. |
| 6 | **Promote to Prod** | If smoke passes, merge staging → main and trigger prod deployment; otherwise, repeat from step 2 with earlier baseline. |
| 7 | **Post‑Rollback Validation** | Monitor prod metrics for 30 min; verify no regression in security alerts (SIEM) and that the triggering CVE condition is no longer observable. |
| 8 | **Incident Documentation** | Log trigger, rollback SHA, timestamps, and mitigation steps in JIRA ticket; update the dependency audit record with new “last good version”. |
| 9 | **Communicate** | Notify stakeholders (Sayim, SecOps, SRE) via Slack #titan-alerts with summary and next‑step plan (e.g., schedule patch upgrade window). |

**Rollback Time Estimate**: ≤ 20 minutes (including test execution) assuming CI resources are available.
